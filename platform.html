The problem

Engineering specifications hold thousands of requirements. A vague one, like "the system shall be fast", can't be tested, and it tends to surface late, when it's expensive to fix.

Reviewing every requirement by hand doesn't scale, and an LLM on its own isn't cheap or predictable enough at that volume. The system had to be fast, measurable, and leave engineers in charge.

    Key trade-offs

    1. 01

      BERT + LLM over LLM for everything

      Classification is high-volume and well defined. A fine-tuned BERT does it in milliseconds, costs almost nothing and gives accuracy I can measure. The LLM only handles the rules that need judgement.

    2. 02

      Concatenation over LLM rephrasing

      Rephrasing context with an LLM sounded smarter. On the evaluation set it didn't beat plain concatenation, and it added latency, cost and a new way to fail. So the simple version shipped.

    3. 03

      Operations on day one over after the first incident

      Queueing, retries, tracing and dashboards shipped with the first version. If nobody can see what a system is doing, it isn't finished.
