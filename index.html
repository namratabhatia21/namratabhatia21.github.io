    // TRADE-OFFS
    
      
    Architecture is mostly saying no.
    
      
    Three diffs where the obvious option lost, and why.
    
    
    
    
    
      
    
        
    adr-001/model-selection.yaml+2 −1
    
        
    - llm: everything+ classifier: bert-finetuned   # 55% → 82%+ llm: rules_needing_judgement
    
        
    A small model for the volume, an LLM for the judgement
    
        
    Classification is high-volume and well defined. A fine-tuned BERT does it in milliseconds, costs almost nothing and gives accuracy I can measure. The LLM only handles the rules that actually need reasoning.
    
      
    
      
    
        
    adr-002/context-building.py+1 −1
    
        
    - context = llm.rephrase(inputs)+ context = concat(inputs)  # same eval score, less latency
    
        
    Tested both, shipped the simpler one
    
        
    Rephrasing context with an LLM sounded smarter. On the evaluation set it didn't beat plain concatenation, and it added latency, cost and a new way to fail. So the simple version shipped.
    
      
    
      
    
        
    adr-003/operations.yaml+3 −1
    
        
    - observability: after_first_incident+ queue: retries + dead_letter+ tracing: every_step+ dashboards: day_one
    
        
    Designed to be run, not just to run
    
        
    Queueing, retries, tracing and dashboards shipped with the first version. If nobody can see what a system is doing, it isn't finished.
